# GMSL Parser Architecture

This package implements the parser for the GoMUD Scripting Language (GMSL). The parser translates an incoming token stream generated by the `lexer` package into an Abstract Syntax Tree (AST). 

## Stack-Based State Machine

Historically, the parser used a recursive descent architecture. This has been replaced by an explicit **stack-based state machine**. This new approach provides several key advantages:
1. **No Call-Stack Overflows**: It explicitly maintains its execution state in a heap-allocated slice instead of utilizing the Go function call stack.
2. **Easier Debugging**: You can peek at the exact sequence of planned parser routines simply by inspecting `p.stack`. 
3. **Simpler Suspension**: This model enables executing the parser in a suspended or step-by-step mode.

### How it Works

The machine is defined inside `Parse()` and relies on two primary stacks:
- **`p.stack` (Execution Stack)**: A stack of `Frame` objects. Each `Frame` represents a unit of analytical work, dictated by its `ParseState` (e.g. `StateFuncDecl`, `StateIfStatement`).
- **`p.nodeStack` (Value Stack)**: A stack of `AstNode` result objects. When a state successfully uncovers and builds an AST node, it pushes it here.

A typical execution flow when a parent state needs a child node:
1. The **parent frame** (e.g. `StateVariableAssignStmt`) recognizes it needs an Expression.
2. It pushes itself *back* onto the stack (suspending itself).
3. It pushes the **child frame** (`StateExpression`) onto the top of the stack.
4. On subsequent loops, the child frame executes, eventually pushing an `Expression` node to the `nodeStack`, and it is popped from the execution stack.
5. The **parent frame** wakes back up, pops the node from `nodeStack`, casts it to an `Expression`, and resumes its work.

### Adding New Language Features

To add a new grammar rule:
1. Define a new `State*` constant in `ParseState`.
2. Add necessary tracker aggregators (e.g. arrays for arguments) inside the `Frame` type if it's a list or complex object.
3. Hook your new token sequence into the `switch frame.State` dispatch block.
4. Make sure your state reads from `p.nodeStack` if it asks child states to run, and always pushes its final result structure to `p.nodeStack`.

### Verification

Any changes to the grammar MUST be validated using the `TestParserRegression` test. The repository maintains a `testdata/` directory containing baseline AST string outputs (`.expected` files). If the parser output mutates unexpectedly, this suite will catch it.
